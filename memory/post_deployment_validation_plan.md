# Post-Deployment Validation Plan — Production (https://car-repair-sys.emergent.host)

## الحالة: بانتظار تأكيد المستخدم اكتمال النشر — لا تبدأ قبل تأكيده صراحةً

## شروط المستخدم الملزمة
- بيانات الاختبار المؤقتة تُعلَّم بوضوح: العميل/المركبة = "TEST - DO NOT USE"، الزيارة = "TEST"
- كل المستندات داخل جلسة اختبار واحدة + تقرير بجميع السجلات المنشأة (IDs)
- حذف جميع بيانات الاختبار بعد التحقق + التأكد من عدم تأثيرها على التقارير/القيود/الإحصائيات
- بيانات الدخول: حساب مدير الإنتاج الحقيقي — المستخدم سيزوّدنا بها بعد النشر إن اختلفت عن التطوير. لا تستخدم بيانات التطوير افتراضياً.

## Checklist التحقق
### المصادقة
- دخول بريد/كلمة مرور، دخول Google OAuth، تجديد Access Token تلقائي، لا حلقة 401، خروج ثم إعادة دخول
### القوالب والمستندات
- إنشاء فاتورة + أمر إصلاح + عرض سعر (بيانات TEST)
- القالب الموحد مستخدم، صفر متغيرات خام، Preview = Print = PDF، طباعة، تصدير PDF، مشاركة واتساب
### الأختام
- اعتماد العميل، اعتماد الورشة، الختم الصحيح يظهر بعد الاعتماد فقط، لا ختم قبل الاعتماد، التحقق من التوقيع الإلكتروني
### الأداء (قياسات مطلوبة في التقرير)
- زمن تسجيل الدخول، تحميل الصفحة الرئيسية، إنشاء المستند، إنشاء PDF، الطباعة، إرسال واتساب
- عدد طلبات API لكل عملية، حجم ملف PDF
- صفر أخطاء Console/Network، تحذيرات Performance
### الأمان
- CORS في الإنتاج، متغيرات البيئة، عدم تسرب Secrets، Security Headers، لا 4xx/5xx غير متوقعة
### التقرير النهائي
- لقطات شاشة لكل خطوة رئيسية + جدول القياسات + قائمة سجلات TEST المنشأة + تأكيد الحذف

## بعد نجاح التحقق
1. الإصدار القادم: صفحة تحقق عامة احترافية للمستندات:
   - داخل المستند: QR + Verification ID فريد + Document Hash + Template Version + Timestamp + Digital Signature Status + Approval Status + Company Info
   - صفحة التحقق العامة تعرض: حالة المستند (صحيح/ملغى/مستبدل)، النوع، الرقم، تاريخ الإصدار وآخر تعديل، بيانات الاعتماد، حالة التوقيع، نسخة القالب، سجل الإصدارات
   - بدون أي بيانات مالية أو حساسة
2. ثم مشروع إعادة تصميم UX/UI وفق الخطة الجديدة
